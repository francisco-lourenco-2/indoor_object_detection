Symmetry Aware and Base Plane Aided 3-Step Rotation Estimation
Introduction:
Following the plan proposed in Alternative methods for classification and rotation, two new experiments were conducted with the aim of improving the performance of the new rotation estimation solution still in development. As a reminder, the proposed solution included the already implemented and reported 3-Step rotation estimation (PCA + Flip Estimation + EPN) plus two additional steps/techniques that I believe can improve the estimator’s performance even further, namely symmetry and base plane detection. Therefore, in this document I am reporting the results obtained by introducing symmetry analysis and base plane detection into the 3-Step solution already described in PCA disambiguation with EPN.

I believe we can find some improvements by adding these techniques to the solution because during my research on rotation estimation methods, I found that geometrical and deep learning based approaches could complement each other. This is because, although geometrical approaches such as PCA or base plane based upright orientation estimation are able to find “perfect” alignment in a lot of cases, such techniques are only able to do so by making assumptions about the 3D model’s geometry that, unfortunately, do not apply to all models. It is exactly when such conditions are not met that deep learning based approaches can be advantageous, allowing us to get good alignment even when geometry fails. I also find this approach to be intuitive in the sense that, when we align a 3D model manually, I believe we are intrinsically searching for symmetries as well as for a base plane and, only in the absence of those visual cues, we align the model based on our knowledge of the world, thus using our own non-artificial neural network.

So, at this point, we already added PCA and posterior disambiguation to our EPN based solution, so now, we are going to look for two geometrical properties in our 3D models: symmetries and base plane. 

As demonstrated in Alignment of 3D models, when a model has one or more planes of symmetry, it is guaranteed that PCA finds at least the same number of good alignment axis, which means that, after our first 2 steps of the 3-Step solution (PCA + Flip Estimation), we can check if the model is symmetric to any of the 3 reference planes xz, xy, and yz. If any symmetry is found, we know that the rotation on the reference axes forming the reflection planes is correct, meaning that we only need to find the rotation on the normal of that plane. For instance, if we find a symmetry on the zy plane (actually the most common one), we only need to find a rotation around the x axis, which is an easier task for EPN and also prevents it from applying further rotations on the z and y axis which would misalign the model. In short, we will be using symmetries for reducing degrees of freedom on the rotation estimation task.

The other geometric property we will be looking for is the base plane of the model. When an animal or an object is in its upright position, there are expected points of contact with the floor, therefore, if we find where those points of contact are, we can easily infer the 3D model upright orientation which, similarly to when symmetries are found, reduces the problem to a single axis rotation. In this case, we only need to find a rotation around the y axis (normal to the reference floor). The only problem with this approach is that not all models stand in a regular position or do not even have planar feet and, in such cases it is very hard to find the points of contact. However, it is totally fine if we don’t find the base plane, because EPN can still estimate a rotation.

Now, having stated how we can leverage geometric properties of the 3D models for improving our rotation estimation solution, let’s now see how the procedure will look like:

The main difference is that, in practice, the symmetry analysis is actually done before base plane detection. If the reflection plane coincides with the base plane (zx), the model is still being send for further alignment. 
Methodology:
Symmetry detection:
As mentioned in the introduction, if the model has symmetries, PCA should find them. Therefore, any reflection plane present in the model should be already aligned with any of the reference planes after PCA and posterior disambiguation. This means that, we only need to check if the pre-aligned model (PCA + Flip estimation) is symmetric to any of the 3 reference planes xy, xz, and yz. To do so, n points are uniformly sampled from the model’s surface originating point cloud P. Then, P is splitted into two point clouds, each on each side of the query reference plane. For example, if we were checking if the model is symmetric to the zy plane, point cloud P is splitted into positive and negative x coordinates. Now, we only need to reflect one of the two point clouds and compare it with the other one. To compute similarity, the mean distance between closest points of the two point clouds is computed. If the two point clouds are identical, then we have a symmetry.

Once this analysis is done, we decide the best way of aligning the model based on the number of symmetries found:

    • 0 symmetries: Send for further processing - 3 degrees of freedom.
    • 1 symmetry: Lock the estimated rotations on the axis forming the reflection plane and send it for further processing - 1 degree of freedom.
    • 2+ -  Lock all three axes and finish the alignment process.
Algorithm settings/details:
    • Number of points being sampled from the meshe’s surface: 100k
    • Symmetry Threshold: 0,01. This means that, when the two subject point clouds have a mean distance between closest points less than 0,01, we consider that the mesh is symmetric in respect to the subject reference plane. Also note that, for this analysis the mesh is being normalised so it fits inside a unit sphere, which means that 0,01 corresponds to 1% of the sphere radius length.

Base plane detection:
The current implementation of the base plane detection mechanism is an improved version of the method presented here Base plane finder, that also accounts for the number of points of contact of the model with the floor. In order to detect the base plane, we first pre-align the model using the symmetry aware 3-Step rotation estimation solution (PCA + Flip estimation + Symmetry aware EPN refinement), then we follow the steps below:

    1. Compute the convex hull of the 3D model.
    2. Remove every triangle on the positive y or whose normals deviate too much from the global floor. (We can do this because the model is pre-aligned)
    3. Cluster triangles with similar normals in order to form candidate base planes.
    4. For each triangle’s base plane, check the equilibrium condition, i.e, if the projected model’s center of mass lies inside it. Discard candidates that do not meet this condition.
    5. Count how many points of contact there are between the model and the floor. Discard any candidate base plane with an unexpected number of points of contact. Note that, for bipeds we expect between 1 and 2 points of contact (some models are not touching the floor with both feet), for quadrupeds we expect 3 or 4, and so on… 
    6. From the remaining candidate bases, select the one that offers more stability to the model, i.e, the base that makes it harder to tip the model over. This is done by calculating the “tip over” angle formed by points C’, C, and P. Where:
C’ - Projected center of mass.
C - Center of mass
P - Closest edge of the candidate base boundary to the projected center of mass.

Here’s a visual representation of the tip over angle:


Note that this algorithm is intentionally designed to produce the minimum amount of false positives as possible, as it is considerably better to not find any base plane than finding the wrong one. Recall that, at this point, the models are already near optimal alignment and this step is only intended to do fine adjustments to the model alignment. Moreover, not all categories are expected to have a base plane, like flying models, bicycles, boats, and etc… For such categories, base plane detection is turned off.
Algorithm settings/details:
    • Angle threshold using in step 2: 45॰
    • Clustering in step 3: To cluster triangles into candidate bases based on their normals, the normals are firstly converted to spherical coordinates, which allows us to plot the normals in 2D based on their polar and azimuthal angles. Then, DBSCAN is used to cluster points of the 2D plot with a max euclidean distance of 2॰.
    • Number of points of contact used in step 5: To count the number of points of contact of the model with the floor, 100k points are firstly sampled from the meshes surface. Then we filter the points based on their distance to the candidate base, meaning that we remove every point with a distance larger than 0.03 from the candidate base (the mesh is normalised so it fits inside a unit sphere). Once we have our filtered point cloud, and considering that all these points should belong to the same plane, we can convert everything to 2D and then use DBSCAN in 2D to find clusters of points. Each cluster of points should belong to the same point of contact, i.e, feet, wheel, paw, etc. So the number of clusters found by DBSCAN should be the same as the number of points of contact.
Single axis rotation estimation:
I am adding this section just to briefly explain how single axis rotation estimation is being performed. As we saw in the sections above, depending on the subject geometric properties of the model, we might want to only rotate the model in one axis and, in such case, a modified version of EPN is used. The original EPN outputs a vector of size 4, which corresponds to the four coefficients of a quaternion, however, when we want to rotate the model in one single axis, we are only interested in one single value, which corresponds to one rotation around the axis of interest. Therefore, EPN is modified so it only regresses one value. Moreover, when training the modified EPN, we only augment the models with slight rotations on the axis of interest. The maximum angle for rotation augmentation varied between 30॰ (15॰ to each side) and 150 (75॰ to each side) depending on the category, as PCA works better for some categories than others but, I should say that I didn’t really noticed that much difference on accuracy when using large and small angles, so a good practice for the future would be to just set this angle high like 150॰ to improve the generalisation of the solution.

I believe it is relevant to mention this because, this minor technicality implies that we will now have 3 more trained networks per alignment category, resulting in a total of 5 networks per alignment category (flip + xyz + x + y + z). This does not impact the inference time of the solution because only 2 of this networks will be used in inference, however, it will require more storage space (not sure if this is a problem, but I thought it would be good to mention 😅).
